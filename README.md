# BizMate - 자영업자 수익 분석 서비스

BizMate는 가게의 상품, 매출, 지출을 관리하고 매출 흐름과 지출 현황을 확인하는 웹서비스입니다. 직접 입력하거나 CSV로 가져온 데이터를 대시보드와 분석 화면에서 활용합니다.

이번 개발은 한 운영자가 로그인 없이 여러 가게를 선택해 관리하는 방향으로 진행합니다. 현재는 가게 구분 없이 세션에 데이터를 보관하며, 가게별 데이터 분리는 앞으로 구현합니다.

## 서비스 목표

자영업자는 판매량과 매출을 확인할 수 있지만, 매출만으로는 가게의 수익 구조를 파악하기 어렵습니다. BizMate는 상품의 판매가와 추정 원가, 매출 및 지출 정보를 함께 관리해 가게 운영 현황을 이해하고 판단할 수 있도록 돕는 것을 목표로 합니다.

- 매출과 지출을 함께 확인하고 기간별 차액 파악
- 상품별 판매량, 매출과 예상 마진 확인
- 지출 분류별 합계와 비중을 통해 비용 구조 파악
- CSV 가져오기로 반복적인 데이터 입력 부담 감소
- 여러 가게의 데이터를 구분해 가게별 운영 현황 확인
- 대시보드와 기본 분석 리포트를 통한 매출 및 지출 변화 파악

## 이번 개발 범위

- 상품, 매출, 지출의 등록, 조회, 수정, 삭제
- 매출과 지출 CSV 업로드, 열 연결, 입력값 확인, 목록 반영
- 실제 데이터를 활용한 대시보드
- 여러 가게의 정보 관리와 가게 선택
- 선택한 가게별 상품, 매출, 지출 및 대시보드 구분
- 기본 분석 리포트
- MySQL과 JDBC/DAO를 통한 데이터 저장 및 조회

로그인, 회원가입, AI 경영 코칭, Excel 파일 지원은 이번 개발 범위에서 제외하고 추후 확장 대상으로 둡니다.

## 현재 구현된 기능

### 상품 관리

- 상품 등록, 목록 조회, 수정 및 삭제
- 판매가와 추정 원가를 이용한 예상 마진 계산
- 상품 등록 시 음수 마진 재확인
- 고유 ID를 이용한 상품 구분
- 수정과 삭제는 저장 버튼을 눌렀을 때 세션 목록에 반영

### 매출 관리

- 판매일시, 상품명, 수량, 품목 합계, 주문번호, 주문 경로 입력
- 매출 등록, 목록 조회, 수정 및 삭제
- 매출 목록의 합계 표시
- UTF-8 CSV 업로드와 실제 데이터 미리보기
- 판매일시, 상품명, 수량, 금액 및 선택 항목의 열 연결
- 품목 합계 또는 단가 기준 선택과 단가 기준의 합계 계산
- 확인 화면에서 입력값을 보완한 후 세션 매출 목록에 일괄 추가

### 지출 관리

- 지출일, 분류, 지출 내용, 금액, 메모 입력
- 지출 등록, 목록 조회, 수정 및 삭제
- 지출 목록의 합계 표시
- UTF-8 CSV 업로드와 실제 데이터 미리보기
- 지출일, 분류, 지출 내용, 금액 및 선택 항목인 메모의 열 연결
- 확인 화면에서 입력값과 메모를 보완한 후 세션 지출 목록에 일괄 추가

### CSV 처리

- 매출과 지출에서 공통 CSV 읽기 코드 사용
- 원본 파일 최대 10MB, 데이터 최대 10,000행 처리
- 파일명, 행 수와 처음 5개 행 미리보기
- 따옴표로 감싼 쉼표, 줄바꿈과 따옴표 문자 처리
- 필수 열, 열 번호 범위, 중복 연결 및 데이터 형식 검사
- 전체 행의 검사가 끝난 뒤에만 목록 반영
- 오류 발생 시 확인 화면의 수정값 유지
- 저장 토큰을 이용해 같은 저장 요청의 중복 반영 방지

테스트용 파일은 [매출 샘플 CSV](samples/sales_sample.csv)와 [지출 샘플 CSV](samples/expense_sample.csv)를 제공합니다.

### 대시보드

- 한국 시간 기준 오늘 매출, 오늘 지출, 오늘 차액 표시
- 오늘을 포함한 최근 7일의 날짜별 매출 차트와 합계
- 최근 7일의 상품명별 판매 수량을 기준으로 인기 상품 TOP 3 표시
- 매출 데이터가 없는 날짜는 0으로 표시

오늘 차액은 오늘 매출에서 오늘 지출을 뺀 금액입니다. 주문 수 집계와 AI 영역의 실제 데이터 연결은 구현하지 않았습니다.

## 현재 데이터 저장 방식

상품, 매출, 지출과 CSV 작업 중 데이터는 `HttpSession`에 임시 보관합니다. 브라우저 세션별로 데이터가 구분되며, 세션이 만료되면 데이터가 사라집니다.

아직 DB 저장과 가게별 데이터 구분은 적용하지 않았습니다. 이후 가게 ID를 기준으로 데이터를 연결하고, 세션의 저장 및 조회 부분을 JDBC/DAO 코드로 교체할 예정입니다.

## 앞으로 구현할 기능

1. 가게 등록, 조회, 수정 및 삭제
2. 현재 관리할 가게 선택과 가게별 데이터 분리
3. 상품, 매출, 지출, CSV 반영과 대시보드에 선택한 가게 적용
4. 기간별 매출과 지출 합계, 차액, 상품별 판매량과 지출 분류별 집계를 제공하는 기본 분석 리포트
5. MySQL 테이블 설계와 JDBC/DAO 연결
6. 전체 기능의 연결 확인과 오류 처리 보완
